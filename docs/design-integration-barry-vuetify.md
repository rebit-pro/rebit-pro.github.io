# План интеграции нового дизайна в Barry + Vuetify

## Цель

Перевести текущий Vue 3 + Vite + Vuetify сайт на визуальный язык выбранного бренда ReBit: строгий инженерный стиль, светлая песочная база, тёмный slate-текст, оранжевый акцент и модульная графика из логотипа.

Визуальная опора: логотип с символом `[R]`, идея модулей/системы/надёжности, палитра `Slate & Sand`.

## Брендовые токены

### Палитра

| Роль | Цвет | Где использовать |
| --- | --- | --- |
| `brand-slate-900` | `#1E293B` | основной текст, заголовки, тёмные блоки, контур логотипа |
| `brand-slate-600` | `#475569` | вторичный текст, иконки, подписи, навигация |
| `brand-orange` | `#F97316` | CTA, активные состояния, ключевые акценты, маркеры |
| `brand-sand` | `#E9DCC6` | мягкие фоновые блоки, схемы, модульная графика |
| `brand-cream` | `#FAF8F5` | основной фон страниц и светлых секций |

### Рекомендуемая карта Vuetify

```ts
colors: {
  primary: '#F97316',
  secondary: '#1E293B',
  info: '#475569',
  success: '#2F9E44',
  warning: '#F59E0B',
  error: '#DC2626',
  background: '#FAF8F5',
  surface: '#FFFFFF',
  'surface-variant': '#E9DCC6',
  'on-surface': '#1E293B',
  'on-background': '#1E293B',
}
```

Важно: текущие `PurpleTheme` и `DarkPurpleTheme` в `src/theme/theme.ts` унаследованы от Barry и всё ещё синие/фиолетовые. Их нужно не удалить сразу, а заменить контролируемо: сначала добавить новую тему, затем переключить `defaultTheme`, затем вычистить старые цвета из SCSS и компонентов.

## Архитектура темы

1. Создать новую тему `ReBitStudioTheme` в `src/theme/theme.ts`.
2. Оставить `DarkPurpleTheme` временно только если нужен тёмный режим; иначе заменить его на `ReBitStudioDarkTheme`.
3. В `src/plugins/vuetify.ts` переключить `defaultTheme` на новую тему.
4. Добавить глобальные CSS variables в `src/styles/landing.scss`:
   - `--rb-color-text`
   - `--rb-color-muted`
   - `--rb-color-accent`
   - `--rb-color-sand`
   - `--rb-color-page`
   - `--rb-radius-card`
   - `--rb-shadow-soft`
5. Убрать прямые цвета из компонентов и заменить их на Vuetify theme colors или CSS variables.

## Компонентные правила Barry + Vuetify

### Кнопки

- Основной CTA: `VBtn color="primary"` с оранжевым фоном.
- Вторичный CTA: `variant="outlined"` или `variant="text"` с цветом `secondary`.
- Скругление оставить умеренным: `rounded="md"` вместо слишком мягкого `lg`, чтобы стиль был инженерным, а не SaaS-игрушечным.
- Текст кнопок без uppercase, как уже задано в `src/plugins/vuetify.ts`.

### Карточки

- `VCard` использовать для повторяемых сущностей: услуги, кейсы, статьи, FAQ.
- Радиус: 6-8px.
- Фон: `#FFFFFF` на `#FAF8F5`.
- Граница: `rgba(30, 41, 59, 0.10)`.
- Hover делать спокойным: лёгкий подъём и усиление тени, без ярких градиентов.

### Секции

- Перейти от текущего тёмного hero-градиента в `src/styles/landing.scss` к светлой first-screen композиции из макета.
- Использовать полноширинные секции, а не вложенные карточки.
- Чередовать фоны:
  - основной: `#FAF8F5`;
  - контентные блоки: `#FFFFFF`;
  - схемы/процесс: `#E9DCC6` с низкой насыщенностью;
  - редкий тёмный акцент: `#1E293B`.

### Иконки

- Продолжить использовать MDI через текущую настройку Vuetify.
- Визуально приблизить иконки к языку логотипа:
  - код: `mdi-code-brackets`;
  - модульность: `mdi-view-grid-outline`;
  - структура: `mdi-select-drag`;
  - надёжность: `mdi-shield-outline`;
  - интеграции: `mdi-connection`;
  - архитектура: `mdi-sitemap-outline`.
- Для brand-знака лучше использовать отдельный SVG/PNG asset, а не собирать его из MDI.

## Логотип и ассеты

1. Подготовить `public/logo-rebit.svg` или `src/assets/logo-rebit.svg`.
2. Подготовить компактную иконку `public/favicon.svg` на основе знака `[R]`.
3. Обновить:
   - `public/favicon.svg`;
   - `public/apple-touch-icon.png`;
   - `public/og-image.png`;
   - шапку `src/components/TopBar.vue`;
   - footer `src/components/SiteFooter.vue`.
4. Проверить, что логотип читается на светлом фоне `#FAF8F5` и в маленьком размере 32px.

## Типографика

Макет использует контраст: выразительные заголовки и спокойный интерфейсный текст.

1. Для заголовков выбрать serif или slab-like гарнитуру, близкую к макету. Если подключение webfont нежелательно, использовать системный fallback:
   - headings: `Georgia`, `Cambria`, `Times New Roman`, serif;
   - body: `Inter`, `Roboto`, `Arial`, sans-serif.
2. Зафиксировать типографические классы:
   - `.rb-heading-xl`
   - `.rb-heading-lg`
   - `.rb-section-title`
   - `.rb-lead`
   - `.rb-caption`
3. Не масштабировать шрифты через viewport width. Использовать `clamp()` только с разумными границами.
4. Убрать отрицательный letter-spacing. Для маленьких overline допустим положительный tracking.

## Графический язык

Визуальный мотив бренда: скобки, сетка, модульность, инженерные схемы.

Реализация:

- добавить фоновые паттерны через CSS:
  - тонкая сетка;
  - пунктирные направляющие;
  - небольшие оранжевые маркеры;
  - прямоугольные sand-блоки;
- не использовать декоративные blob/orb-градиенты;
- для hero подготовить модульную 3D/isometric иллюстрацию или статичную композицию из блоков;
- повторять знак скобок `[ ]` как микро-мотив в overline, списках и CTA.

## Миграция по компонентам

### 1. `TopBar.vue`

- Заменить текстовый/текущий бренд на новый логотип.
- Перекрасить навигацию в `#475569`.
- Активный/hover цвет: `#F97316`.
- CTA в шапке сделать outlined или compact primary.

### 2. `HeroSection.vue`

- Перевести на светлый фон.
- Структура hero:
  - overline в формате `[ надёжный код, человеческий подход ]`;
  - H1: конкретный оффер;
  - лид-абзац;
  - primary CTA;
  - secondary CTA;
  - модульная графика справа или ниже на mobile.
- Убрать фиолетово-синие градиенты.

### 3. `ServicesSection.vue` и `TasksSection.vue`

- Карточки услуг сделать более плотными и инженерными.
- Добавить иконки в slate/orange.
- Для каждой услуги заранее заложить `slug`, чтобы потом перейти к SEO-страницам.

### 4. `ArchitectureSection.vue` и `StackSection.vue`

- Использовать визуальный язык модулей: сетки, блоки, связи.
- Оставить архитектурный тон, но убрать ощущение тёмного admin-template.

### 5. `ProjectsSection.vue`

- Перевести проекты в формат кейсов:
  - задача;
  - решение;
  - результат;
  - стек;
  - связанная услуга.
- Карточки сделать светлыми, с оранжевым маркером статуса/результата.

### 6. `ProcessSection.vue`

- Подать процесс как структурную схему: шаги, соединительные линии, номера.
- Фон можно сделать `#E9DCC6` или светлый с sand-акцентами.

### 7. `FaqSection.vue`, `ContactSection.vue`, `SiteFooter.vue`

- FAQ оставить максимально читаемым, без тяжёлых визуальных эффектов.
- Контакты усилить CTA-кнопкой.
- Footer сделать на `#1E293B` с оранжевыми активными ссылками.

## Этапы внедрения

### Этап 1. Дизайн-токены

- Добавить `ReBitStudioTheme`.
- Переключить Vuetify default theme.
- Вынести CSS variables.
- Проверить `npm run build`.

### Этап 2. Брендовые ассеты

- Добавить логотип и favicon.
- Обновить `TopBar`, `SiteFooter`, meta/OG assets.
- Проверить отображение на desktop/mobile.

### Этап 3. Первый экран и общий фон

- Переработать `HeroSection`.
- Заменить глобальный фон `.site`.
- Настроить базовые секции `.section`, `.surface-card`.

### Этап 4. Компоненты и карточки

- Последовательно пройти секции:
  - аудитории;
  - услуги;
  - задачи;
  - архитектура;
  - стек;
  - кейсы;
  - процесс;
  - FAQ;
  - контакты.
- Убрать прямые старые цвета и фиолетово-синий Barry-след.

### Этап 5. Проверка

- `npm run build`.
- Ручная проверка desktop и mobile.
- Проверка контраста текста.
- Проверка, что CTA и ссылки имеют единый hover/focus.
- Проверка, что нет визуального конфликта между `ReBit Studio` из макета и текущим позиционированием `ReBit Systems`.

## Критерии готовности

- Цвета из макета представлены в теме Vuetify и CSS variables.
- Старые Barry purple/blue цвета не используются в пользовательском интерфейсе без причины.
- Логотип читается в шапке, footer, favicon и OG preview.
- Основные компоненты используют единые размеры, радиусы, hover/focus и типографику.
- Сайт выглядит как инженерная студия/команда, а не как персональное портфолио на admin-template.
- Сборка проходит без ошибок.
